# Signova product prototype

## Goal
Build an interactive, accessibility-first Signova product prototype that clearly demonstrates the Deaf-user tablet/mobile application, the hearing-staff dashboard, and the organisation admin portal. The tablet experience receives the strongest visual emphasis.

## Product structure
- Add a role switcher for **Deaf User**, **Staff**, and **Admin** without making the tablet experience feel like a desktop dashboard.
- Make the Deaf-user application the default first screen, presented as a dedicated counter tablet with touch-first controls.
- Provide a mobile adaptation that reorganises controls and camera content rather than merely shrinking the tablet layout.
- Add desktop staff and admin workspaces that visually belong to the same Signova system.

## Deaf-user tablet and mobile application
- Build the complete guided journey: splash, organisation welcome, communication method, staff connection, camera permission, ready-to-sign, live recognition, processing, confirmation, sent state, two-way conversation, staff response, low-confidence recovery, connection interruption, completion, accessibility settings, and help.
- Make the flow interactive so primary and secondary actions move naturally between states.
- Keep camera space dominant, translations readable, controls large, feedback explicit, and audio optional.
- Include realistic Kenyan context and dignified representation through purpose-made imagery.
- Include an organisation-branded welcome example to demonstrate white-labelling.

## Staff dashboard
- Create a desktop workspace with incoming requests, session acceptance, session details, the live conversation, text/speech response controls, translation status, session ending, and history.
- Use the requested left information / centre conversation / right system-status arrangement for active sessions.

## Organisation admin portal
- Create navigation and representative views for overview, staff, services, organisation profile, analytics, accessibility, security, and settings.
- Build a working white-label branding editor for logo, organisation name, colours, welcome message, and service information.
- Show changes immediately in a live tablet preview.

## Visual and interaction system
- Establish Royal Purple, Cornsilk, neutral, success, warning, and error tokens with strong contrast.
- Use warm modern typography, restrained motion, subtle corners, clear focus states, large touch targets, and generous spacing.
- Create reusable buttons, navigation, camera, conversation, translation status, alert, success/error, accessibility, and branding controls.
- Avoid generic AI styling, WhatsApp-like chat, dense dashboards, stereotypical motifs, and excessive purple.

## Accessibility and verification
- Use semantic headings and landmarks, descriptive image text, labelled controls, keyboard-visible focus, status announcements, and reduced-motion support.
- Verify the main journey at tablet and mobile widths, and the web workspaces at desktop width.
- Check that camera content, long text, controls, and navigation do not overlap or become too small.
- Add unique page metadata for the Signova prototype.

## Delivery note
The result will be an interactive app prototype in this project. Direct editing of a Figma file requires the Lovable Desktop/Figma connection, which is not currently active; the finished prototype can still serve as the implementation-ready design reference.
