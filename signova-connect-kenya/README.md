# Signova Connect (20)

Design a beautiful, modern, accessibility-first **mobile and tablet application for Signova**, an AI-powered communication system that enables Deaf and hard-of-hearing users to communicate with hearing staff at institutional service counters.

## IMPORTANT — PRODUCT TYPE

**Signova's Deaf-user interface is a MOBILE/TABLET APPLICATION.**

It is NOT a web application.

The primary device for deployment is a **tablet placed at an institutional service counter**, while the application should also adapt naturally to smaller mobile screens.

Design the Deaf-user experience as a genuine mobile/tablet application with:

* Touch-first interaction

* Large touch targets

* Mobile navigation

* Tablet-optimised layouts

* Large camera interaction area

* Simple gestures

* Clear visual feedback

* Minimal cognitive load

* Accessibility-first UX

Do NOT make the Deaf-user interface look like a desktop dashboard.

The tablet should feel like a **dedicated communication device at a hospital, bank, government office, university, pharmacy or other service counter.**

---

# SIGNOVA CONCEPT

Signova bridges communication between:

**DEAF USER**

Mobile / Tablet App

↓

Sign Language

↓

**SIGNOVA AI SIGN RECOGNITION**

↓

Text / Speech

↓

**HEARING STAFF**

Web Dashboard

The hearing staff member responds through the web dashboard using speech or text.

The response is delivered back to the Deaf user's tablet/mobile application.

This creates a **two-way communication experience**.

---

# PRIMARY DESIGN PRIORITY

The Deaf user is the primary focus of this design.

Spend the majority of the design effort on creating an exceptional Deaf-user mobile/tablet experience.

The interface must feel:

**Simple

Safe

Human

Welcoming

Fast

Accessible

Modern

Dignified**

A Deaf user should be able to walk up to the tablet and understand what to do **without needing someone to explain the interface.**

# VISUAL IDENTITY

Use **ROYAL PURPLE and CORNSILK** as Signova's primary brand colours.

### Primary colour

**Royal Purple**

Use it for:

* Primary buttons

* Active navigation

* Important actions

* Selected states

* Brand elements

* Key UI accents

### Secondary/background colour

**Cornsilk**

Use it as:

* Warm background

* Surface colour

* Conversation areas

* Cards

* Empty states

* Accessible visual contrast areas

Use white, near-black and neutral grey as supporting colours.

The overall visual feeling should be:

**Royal Purple + warm Cornsilk + clean neutrals**

Do not make the application overwhelmingly purple.

Use purple strategically against the warm corn silk background.

The result should feel elegant, warm and premium rather than childish.

---

# KENYAN VISUAL IDENTITY

Signova should feel **naturally Kenyan**.

Do NOT make it look like a generic Western accessibility application.

Use realistic representation of:

* Black Kenyan people

* Different Kenyan skin tones

* Young adults

* Older adults

* Men and women

* Deaf users

* Hearing staff

Use realistic Kenyan environments such as:

* Hospital reception

* Bank service counter

* Government office

* University service desk

* Pharmacy

* Customer service centre

The Kenyan identity should come primarily through **people, environments and context**.

Do NOT cover the UI in African patterns.

Do NOT use stereotypical "African" decorations.

Do NOT make it look like a tourism website.

The goal is:

**A world-class accessibility product designed for Kenyan users.**

# UX PRINCIPLES

Follow these principles throughout the entire design:

### 1. Accessibility First

Accessibility is the foundation of the product.

### 2. Visual First

The Deaf user should never need to depend on audio.

### 3. Minimal Cognitive Load

A user should immediately understand what to do.

### 4. Large Interaction Areas

Design for real tablet interaction, not tiny smartphone buttons.

### 5. Clear Feedback

Always communicate:

What Signova is doing.

What it detected.

What it translated.

What happened to the message.

### 6. User Control

Allow the Deaf user to retry, edit or confirm translations.

### 7. Dignity

Never portray Deaf users as helpless.

Show them as confident, independent users of technology.

### 8. Privacy

Clearly communicate when camera/microphone features are active.

# FINAL PRODUCT STORY

When someone views the Figma prototype, they should immediately understand:

**Signova is an accessibility platform.**

The **Deaf user interacts primarily through a tablet/mobile application.**

The **hearing staff member uses a web dashboard.**

The **organisation administrator manages the system through a web portal.**

The organisation can **white-label the Deaf-user experience** with its own branding.

The AI sits between both sides and enables:

**SIGN → TEXT**

and

**SPEECH/TEXT → ACCESSIBLE RESPONSE**

The Deaf-user tablet application should receive the **largest visual emphasis**, because this is the primary user experience and the heart of Signova.

Design the result as if Signova is a **real product preparing for deployment in Kenyan institutions**, not merely a university prototype.
