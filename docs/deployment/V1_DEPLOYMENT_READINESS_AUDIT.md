## 5. PWA and model assets discovered

| Asset | Size | Notes |
|---|---:|---|
| `signova_model.tflite` | 1,332,256 bytes | V1 model, 2,000 classes |
| `labels.json` | 26,018 bytes | 2,000 labels, first 13 match WLASL v0.3 order |
| `model_info.json` | 479 bytes | Contract metadata |
| `hand_landmarker.task` | 7,819,105 bytes | MediaPipe hand landmarker |
| `public/wasm*` | ~73.5 MB | LiteRT + MediaPipe runtimes |

Production build observed: **46 precache entries, ~86.3 MB** in `dist`.

**Audit finding (fixed):** the Workbox glob did not include `.task`, so
`hand_landmarker.task` was absent from the precache and offline recognition
would have failed. The glob now includes `task` and `webmanifest`.

**Audit finding:** the PWA stores the session access token and session record in
`localStorage` (`signova.accessToken`, `signova.session`) so an installed app can
resume. This is an accepted risk for the kiosk model but is XSS-sensitive.
Mitigations: HTTPS, no third-party scripts in the PWA, short access-token TTL,
and eventual migration to a safer storage strategy.

## 6. Secrets and development-only content

**Critical finding (neutralized, follow-up required):**
`apps/web-admin-portal/public/auth_bridge.html` contained a real administrator
access token, refresh token, and user record, and was copied into the public
build. The file has been replaced with a disabled placeholder. Because the old
content remains in git history:

1. Rotate `ACCESS_TOKEN_SECRET`, `REFRESH_TOKEN_SECRET`, and
   `CHALLENGE_TOKEN_SECRET` before production.
2. Revoke all refresh tokens for the exposed administrator
   (`revokeAllRefreshTokens` / re-login on all devices).
3. Treat the exposed refresh token as compromised even though it was short-lived.
4. Do not rewrite git history without explicit owner approval.

Other development-only items:

- `server/.env`, app `.env*` files, `server/src/storage/videos/*`, `dist/`
  folders, and temporary `tmp_*`/`rltest*` scripts are present in the working
  tree. They are mostly gitignored, but committed `dist/` output exists.
- The PWA `.env` currently contains a dev-tunnel API URL. Netlify must override
  it with `VITE_API_URL=https://api.<SIGNOVA_DOMAIN>`.
- `GOOGLE_REDIRECT_URI` appears in `server/.env.example` but is not used by the
  current ID-token Google flow; do not treat it as required.
